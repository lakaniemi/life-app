# app

React Native + Expo (SDK 58) app, using [Expo Router](https://docs.expo.dev/router/introduction) for file-based routing. The design is in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Setup

- **Node** from `.nvmrc` (`nvm use`).
- **Android Studio**, with an emulator (Device Manager). The first build downloads the NDK, CMake and build tools it needs into the Android SDK.
- **A JDK** for Gradle. React Native recommends JDK 17; JDK 21 also works.
- `npm ci`

## Running

The app runs as a **development build**, not in Expo Go: our own native app with `expo-dev-client`, which loads its JavaScript from Metro with fast refresh.

```bash
npm run android   # build and install "Life App Dev", then start Metro
npm start         # later: just Metro, for the dev build already installed
```

Rebuild with `npm run android` only when native code changes: a native dependency is added or upgraded, or `app.config.ts` or a config plugin changes. JavaScript changes only need Metro.

A physical phone works too, over USB with debugging on. The dev build loads JavaScript from Metro at the Mac's LAN address, so the phone needs the same network, or `adb reverse tcp:8081 tcp:8081`.

### Local API

The dev variant calls the API at `http://10.0.2.2:8080`, the emulator's address for the Mac's `localhost`, so run the API locally (`api/README.md`). A physical phone can't use that address. Either run `adb reverse tcp:8080 tcp:8080` and start Metro with `API_URL=http://localhost:8080 npm start`, or set `API_URL` to the Mac's LAN address. The URL comes from Metro's config, so changing it only needs a Metro restart, not a rebuild.

## Variants

`APP_VARIANT` selects the variant in `app.config.ts`. Both install side by side:

| Variant | `APP_VARIANT` | Package | Name | Scheme | API |
| --- | --- | --- | --- | --- | --- |
| Dev | `development` (default) | `com.lakaniemi.lifeapp.dev` | Life App Dev | `lifeapp-dev://` | `http://10.0.2.2:8080` |
| Prod | `production` | `com.lakaniemi.lifeapp` | Life App | `lifeapp://` | `https://life-app-api.lakaniemi.com` |

`npm run android:prod` builds the production variant as a release build, with the JavaScript bundled into the APK. Until release signing is set up it's signed with the debug key, so it's for local testing only.

`android/` is generated by `expo prebuild` and gitignored. The build scripts regenerate it for their variant, so never edit it by hand.

## Checks

```bash
npm run lint
npm run typecheck
npm test
```

CI runs these, plus `npx expo install --check`, which fails when a package drifts from the SDK's versions.
