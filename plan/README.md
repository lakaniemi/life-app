Temporary working docs. **Delete `plan/` once the last phase lands.** Durable decisions move into the root `CLAUDE.md` decisions table as each phase merges.

## Goal

Users sign in with Google and belong to one or more families. Most future app data (meals, shopping lists, health) belongs to a family, and users reach it through their membership.

## Decisions

| Area        | Decision                                                                              |
| ----------- | ------------------------------------------------------------------------------------- |
| Migrations  | goose: plain SQL files embedded in the binary, run by our own `cmd/migrate`           |
| DB access   | pgx/v5 + pgxpool, queries generated by sqlc (generated code committed)                |
| Auth        | App does Google sign-in natively; API verifies the ID token and issues its own opaque session token |
| Identity    | `users.google_sub`; no email stored                                                   |
| Tenancy     | Many-to-many users ↔ families in DB/API; the app starts with a single family         |
| Joining     | Invite code, shown and scanned as a QR code                                           |
| Roles       | `admin`, `member`                                                                     |

## Prerequisites (owned by you)

1. **Production database: unknown for now.** All phases here are built and tested against local Docker Postgres. Choosing the production database (and deploying) is a separate decision; see root `CLAUDE.md`.
2. **Google Cloud:** set up the OAuth consent screen and a **Web** OAuth client ID before phase 2. iOS/Android client IDs come in phase 5.

## Open questions

- **Production database location.** It blocks deployment, but not these phases.
- **When migrations run in deployment.** The options are a one-off job before each deploy, or startup with an advisory lock. Decide when `infra/` exists.
- **Account deletion** isn't in scope. When it's added, it must apply the sole-member/sole-admin rules before cascading.
- **Sign in with Apple** is only needed if the app ships publicly on the App Store (guideline 4.8). The schema change is small; see the data model doc.
